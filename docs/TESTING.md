# Testing

## Commands

```bash
.venv/bin/python -m pytest              # Python unit + integration + end-to-end service tests
node --test web/tests/*.test.mjs        # JavaScript unit tests (Node 18+)
for f in $(find web/js -name '*.js'); do node --check "$f"; done   # JS syntax check
.venv/bin/python -m archestral analyze tests/fixtures/synthetic/noisy_90bpm.json   # offline analysis report
.venv/bin/python -m archestral diagnose --camera 0                   # dependency + camera probe
```

## Results on the development machine (macOS 26.0.1, Apple M2, Python 3.12.4, Node 22.23)

- `pytest`: **98 passed** (about 22 s)
- `node --test`: **12 passed**
- `node --check` on all client modules: no errors

## Test data
`tests/fixtures/synthetic/` contains **synthetic** trajectories generated by
`python -m archestral gen-fixtures` (seed 20261025): reference 90 BPM, faster 120, slower 60, noisy,
incomplete, invalid timestamps, and missing samples. No real webcam recordings are included or
presented as such.

## Manual browser checks performed (Chromium, in-app browser pane)
- Main menu, first-run dialog, status chips.
- Conductor with recorded test data (120 BPM fixture): estimate 120.0 BPM, similarity 0.89,
  beats labelled 1–4, test-input banner shown.
- Conductor with mouse input (synthetic pointer events at 90 BPM): 90.0 BPM, 0.0% deviation,
  7 ms timing error. Stop opened the Results page with the tempo chart.
- Webcam selected without camera permission: the "Camera unavailable" banner with instructions appeared, and the app kept working.
- Composer: stage rendered, selection, solo, keyboard move with a collision stop, playback, and
  measured L/R levels changing with position (R>L by ~3 dB at x=+3; L>R by ~4 dB at x=−1.5).
- A/B compare dialog with the measured difference table.
- Settings and Diagnostics pages.
